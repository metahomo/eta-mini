- **환경 사고**: `mlops-sample`은 상위 폴더 `Projects/`의 **uv workspace 멤버**라서 상위 `.venv`를 함께 쓴다. 그런데 이 `.venv`에서 fastapi와 httpx2가 사라졌다 → `uv run pytest`가 **아무것도 출력하지 않고 exit 1**로 끝난다. 원인은 모른다 (같은 workspace의 다른 프로젝트에서 sync를 했을 가능성). 공용 환경이라 손대지 않았고, 앱 코드가 같은 실험 worktree의 독립 venv에서 탐색했다
  - 배운 점: workspace 멤버는 가상환경을 공유한다 → 옆 프로젝트의 작업이 내 테스트를 깨뜨릴 수 있다

**계약을 어기는 동작 (테스트를 쓰면 지금 실패함)**
| 입력 | 결과 |
|---|---|
| `pending_orders: 999…9` (400자리 정수) | **500** |
| JSON `NaN` | **500** |
| `distance_km: 1e308` / `1e309` / `Infinity` / `"inf"` | 200 `minutes: null` |

**계약이 애매한 동작 (결정이 필요함)**: `"2"`, `" 2 "`, `true`/`false`, 주문 수 `2.0`/`1e2`, 중복 키(마지막 값이 이김), 정의되지 않은 추가 필드, `-0.0` → 모두 200

**계약대로 동작하지만 테스트가 없는 것**: 본문이 배열/`null`/빈 본문 → 422, 빈 문자열 → 422, 값이 배열·객체 → 422, 400자리 정수 거리 → 422, `"1e2"` 문자열 주문 → 422, `"NaN"` 문자열 → 422, `-0.01`, `GET /eta`·`POST /health` → 405, 증가량(주문 1건 = 2분, 1km = 3분)
- 흥미로운 점: JSON `NaN`은 500인데 문자열 `"NaN"`은 422다 (`ge=0` 비교에서 NaN이 거짓이 되어 걸림). 같은 값이라도 **어떤 경로로 들어오느냐에 따라 결과가 다르다**

### 7) C 목록(계약대로 동작하는 엣지 케이스) 테스트 추가
- **목록을 바로잡음**: 추가하기 전에 다시 검토해서 두 항목을 뺐다
  - 400자리 정수 거리 → 422: 계약은 "0 이상 실수"만 정한다 → 422를 정답으로 볼 근거가 없음 (실제로는 판단이 필요한 항목)
  - minutes가 숫자인지: 기존 `test_eta_response_shape`와 중복
  - 배운 점: "현재 동작 = 계약"이라고 쉽게 분류하는 실수를 했다. 테스트로 굳히기 전에 **각 기대값이 계약의 어느 문장에서 나왔는지** 다시 확인해야 한다
- `api/tests/test_api.py`에 케이스 16개 추가 (22 → **38 passed**)
  - 422 parametrize 9개: `-0.01`, 빈 문자열·배열·객체 (두 필드 각각), `"NaN"` 문자열, `"1e2"` 문자열 주문 수
  - `test_eta_body_not_object_returns_422`: 본문이 배열 / `null` / 비어 있음
  - `test_wrong_method_returns_405`: `GET /eta`, `POST /health`
  - `test_eta_each_pending_order_adds_two_minutes`, `test_eta_each_km_adds_three_minutes`: 증가량
- 공용 venv가 깨져 있어서 **실험 worktree의 venv로 main의 테스트를 실행**했다 (`<venv>/python -m pytest`)

**일부러 버그 넣기**
| 넣은 버그 | 결과 |
|---|---|
| 주문 1건당 2분 → 3분 | 4 failed (증가량 테스트 포함) ✅ |
| 반환값 `+1` | 5 failed. 증가량 테스트는 통과 (상수는 상쇄됨 — 예상대로) |
| 원래대로 되돌린 뒤 | 38 passed |

- 배운 점: **값 테스트와 증가량 테스트는 서로 다른 버그를 잡는다.** 상수 오류는 값 테스트가, 계수(기울기) 오류는 둘 다 잡는다. 증가량 테스트는 실패했을 때 **어느 항이 틀렸는지** 바로 알려 준다

### 8) uv workspace 문제 해결과 커밋
- 원인: 상위 `Projects/pyproject.toml`의 `[tool.uv.workspace] members`에 `mlops-sample`이 들어 있었다 → 가상환경(`Projects/.venv`)과 `uv.lock`을 루트에 하나만 두고 공유했다. 하위 폴더에서 `uv init`을 하면 자동으로 멤버가 된다
- 공유 venv에서는 다른 멤버가 `uv sync`를 하면 내 패키지가 지워질 수 있다 (uv sync는 기본적으로 필요 없는 패키지를 제거함)
- 사용자가 직접 workspace에서 분리함 → `mlops-sample/.venv`, `mlops-sample/uv.lock`이 생기고 `uv run pytest -q` **38 passed**로 복구
- 방지: 새 프로젝트는 `uv init --no-workspace`로 만든다. 프로젝트를 모아 두는 상위 폴더를 uv 프로젝트로 만들지 않는다
- 커밋: `.vscode/settings.json`(pytest 설정) → `73469d3`, 테스트 2개 파일 → `ca1cae9`, 머지 `3b140f2`

## 3. 핵심 개념 정리

- **계약 테스트 (contract test)** — 구현이 아니라 외부와 약속한 입출력(상태 코드, 응답 형식, 값)을 확인하는 테스트 — `/health`, `/eta`
- **테스트 오라클 (test oracle)** — 정답을 어디에서 가져오나. 현재 코드의 출력을 정답으로 쓰면 버그까지 굳어 버린다 — `AGENTS.md`의 사장님 규칙 표
- **변이 테스트 (mutation check)** — 코드에 일부러 버그를 넣어 테스트가 실패하는지 본다 — `+1` 넣기, `ge=0` 빼기
- **Pydantic lax / strict** — lax는 `"2"`→2, `true`→1처럼 형 변환을 허용하고 strict는 거부한다 — `EtaRequest`
- **에이전트 지침 파일 (`AGENTS.md` / `CLAUDE.md`)** — 매번 프롬프트에 쓰지 않아도 되는 규칙을 저장소에 둔다 → 프롬프트가 한 줄이 된다
